# Campus Events API Contract (Week 6)

## Base URL

`http://localhost:3000`

All request and response bodies use JSON.

Errors follow NestJS format:

```json
{
  "statusCode": 400,
  "message": ["Validation error"],
  "error": "Bad Request"
}
```

## 1. Resources

### Event

| Field       | Type / Rules                            |
| ----------- | --------------------------------------- |
| id          | Integer, generated by server            |
| title       | String, 3–100 characters                |
| category    | talk, workshop, social, or sport        |
| startsAt    | Valid ISO 8601 date                     |
| location    | String, 1–100 characters                |
| capacity    | Integer, 1–1000                         |
| booked      | Integer, controlled by server           |
| description | Optional string, maximum 500 characters |

### Booking

| Field     | Type / Rules                       |
| --------- | ---------------------------------- |
| id        | Integer, generated by server       |
| eventId   | Integer                            |
| name      | String, 2–100 characters           |
| email     | Valid email address                |
| seats     | Integer, 1–4                       |
| createdAt | ISO 8601 date, generated by server |

## 2. API Endpoints

| Method | Path                        | Body               | Success        |
| ------ | --------------------------- | ------------------ | -------------- |
| GET    | `/events?category=&search=` | None               | 200 Event[]    |
| GET    | `/events/:id`               | None               | 200 Event      |
| POST   | `/events`                   | Event details      | 201 Event      |
| PATCH  | `/events/:id`               | Fields to update   | 200 Event      |
| DELETE | `/events/:id`               | None               | 204 No Content |
| GET    | `/bookings`                 | None               | 200 Booking[]  |
| POST   | `/events/:id/bookings`      | name, email, seats | 201 Booking    |
| DELETE | `/bookings/:id`             | None               | 204 No Content |

## 3. Validation and Error Responses

- **400 Bad Request:** Invalid input, invalid ID, or unknown properties.
- **404 Not Found:** Requested event or booking does not exist.
- **409 Conflict:** Not enough seats are available for a booking.
- Event titles must contain 3–100 characters.
- Booking names must contain 2–100 characters.
- Booking emails must have a valid email format.
- Booking seats must be between 1 and 4.
- Event capacity must be between 1 and 1000.
- The server controls event IDs and booking counts.

## 4. Authentication and Roles

Authentication is not implemented in Week 6.

All endpoints are currently accessible without logging in. There are no role-based permissions in this version.

Authentication is planned for Week 8.

## 5. Features Not Included

- Authentication: planned for Week 8.
- Pagination: planned for Week 11.

## 6. Notes

- Events are sorted by their start date.
- Bookings are sorted newest first.
- Creating a booking increases the event's booked seat count.
- Cancelling a booking returns the seats to the event.
- Event and booking data are stored in memory and reset when the server restarts.
